# 静悦物料、贵金属计价、盘点与旧料转换改造方案

> 文档状态：方案评审稿  
> 编写日期：2026-11-04  
> 适用范围：ZrAdminNetCore PC 端、JingYueMiniProgram 小程序端、SQL Server 数据库  
> 重要说明：本文只描述改造方案、字段建议和验收标准，不包含可执行 SQL，也未修改任何数据库表或业务数据。正式实施前需先完成第 15 节“待确认事项”的评审。

## 1. 改造目标

本次改造要解决五类业务问题：

1. 建立独立的物料库存体系，支持物料分类、供应商、按重量入库/出库、库存和历史流水。
2. 支持足金、18K、足银及后续新增贵金属的按克/按件计价，销售时使用当前有效价格，并保留成交价格快照。
3. 建立正品盘点和物料盘点，输出统一的综合盘点报表。
4. 将会员折扣从“整单统一折扣”升级为“会员等级 + 商品品类 + 计价方式”的折扣矩阵。
5. 支持截料、旧料回收、料组合和改制，能够追溯旧料到新商品的来源关系和成本归属。

## 2. 现状与影响面

### 2.1 现有可用能力

| 能力 | 现状 | 处理建议 |
| --- | --- | --- |
| 货品库存 | `jy_goods_item` 一行代表一件货品，按件管理 | 继续服务正品库存，不承载物料重量库存 |
| 入库单 | `jy_inbound`、`jy_inbound_line` 已支持供应商、货品、重量、成本、图片 | 保留，补充计价方式、内含数量、工费 |
| 供应商 | `jy_supplier` 已有独立档案，PC 端在“静悦基础 -> 数据字典 -> 供应商档案”维护 | 物料直接引用，禁止另建供应商字典 |
| 库存流水 | `jy_stock_ledger` 只有数量变化，没有重量变化 | 正品流水继续使用，物料新增独立重量流水 |
| 销售单 | `jy_sale_order`、`jy_sale_order_item` 已有成交价、折扣、抹零、退货 | 保留，补充计价快照和明细折扣快照 |
| 会员等级 | `jy_member_level.DiscountRate` 为整单统一折扣 | 保留为默认折扣，新增折扣矩阵表 |
| 盘点 | 只有库存流水中的“盘点”类型，没有盘点单 | 新增盘点单和盘点明细 |
| 金价/银价 | 无 | 新增贵金属价格表 |
| 截料/旧料 | 无 | 新增物料转换单和转换明细 |

### 2.2 必须优先解决的现有口径问题

当前 `jy_goods_item.Qty` 同时承担过“库存件数”和“本件内含数量”两种含义：

- 入库单头 `TotalQty` 按明细行数统计。
- 入库明细 `Qty` 表示本件内含数量，例如 1 对、2 套、5 颗。
- 销售时对 `ItemMode = 1` 又强制数量为 1。

如果不先统一口径，盘点会把“内含数量”和“可售件数”混在一起，按件销售也会出现库存扣减错误。

建议最终口径：

| 字段 | 最终含义 |
| --- | --- |
| `Qty` | 当前可售库存件数，单件唯一货品固定为 1 |
| `InnerQty` | 本件内含数量，例如 1 对、5 颗、2 套 |
| `Unit` | 内含数量的计量单位，例如条、颗、对、件、套 |
| `Weight` | 单件净重，单位克 |
| `PricingMode` | 计价方式，1 按件，2 按克 |

历史数据迁移必须先核对，再分批处理，不能直接把现有 `Qty` 全部覆盖为 1。

### 2.3 预计改动范围

| 模块 | 改动量 | 主要风险 |
| --- | --- | --- |
| 物料档案与出入库 | 中等 | 库存并发、负库存、单据幂等 |
| 贵金属价格与按克销售 | 大 | 销售核心金额计算、历史单据追溯、退货 |
| 会员折扣矩阵 | 中等偏大 | 折扣优先级、整单与明细金额一致性 |
| 盘点 | 中等 | 账面库存快照、确认时并发调整 |
| 截料与旧料转换 | 大 | 库存血缘、成本分摊、客户旧料权属 |

建议分五期实施，不建议一次性上线。

## 3. 总体架构

### 3.1 业务域拆分

```text
正品域
  jy_goods_style / jy_goods_item
  按件库存、条码、证书、图片、销售、退货

物料域
  jy_material / jy_material_doc / jy_material_doc_line / jy_material_ledger
  按克库存、供应商、物料出入库、重量流水

价格域
  jy_metal_price
  足金、18K、足银及其他金属的按克价格和生效区间

营销域
  jy_member_level_discount
  会员等级 + 品类 + 计价方式的折扣矩阵

盘点域
  jy_stocktake / jy_stocktake_line
  正品盘点、物料盘点、综合报表

转换域
  jy_material_conversion / jy_material_conversion_line
  截料、旧料回收、料组合、改制和来源追溯
```

### 3.2 核心设计原则

1. 物料与货品分开库存，不把重量库存塞进 `jy_goods_item`。
2. 所有库存变化必须经过单据确认和流水记录，不允许直接改余额。
3. 金价由服务端取当前有效价格，前端传入的价格只能作为展示值。
4. 销售明细保存价格和折扣快照，历史单据不随金价变化。
5. 会员折扣按明细计算，订单头只做汇总。
6. 截料和旧料转换保留输入、输出、损耗和成本分摊关系。
7. 所有确认动作必须幂等，重复提交不能重复扣减库存。
8. 所有金额统一使用 `decimal`，禁止浮点数。

### 4.6 物料出入库流程

```text
新建草稿
  -> 选择方向、业务类型、供应商
  -> 添加物料和重量
  -> 保存草稿
  -> 确认单据
       -> 校验租户、门店、供应商状态
       -> 校验物料状态
       -> 出库时锁定物料行并校验可用重量
       -> 更新 StockWeight 和 AvgCostPerGram
       -> 写入物料流水
       -> 单据改为已确认
```

出库校验：

```text
可用重量 = StockWeight - LockedWeight
出库重量 <= 可用重量
```

确认接口必须使用数据库事务和行锁，并检查单据状态，防止重复确认。

### 4.7 供应商

物料继续引用 `jy_supplier`：

- 物料档案上的 `SupplierId` 是默认供应商。
- 物料入库单上的 `SupplierId` 是本次实际供应商。
- 两者都可以为空，但采购入库建议必填。
- 停用供应商不能新建入库单，但历史单据仍可查询。

## 5. 贵金属价格与按克/按件计价

### 5.1 金属类型扩展

不要写死足金、18K、足银。继续使用金属/成色字典：

- 足金、18K、22K、足银等都作为 `jy_lookup_item` 字典项。
- 新增金属类型时只维护字典和价格，不改代码。

### 5.2 贵金属价格表 `jy_metal_price`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `Id` | bigint identity | 主键 |
| `TenantId` | nvarchar(64) | 租户 |
| `MetalItemId` | bigint | 金属/成色字典项 |
| `QuoteMode` | int | 1 直接报价，2 按基准金属折算 |
| `BaseMetalItemId` | bigint null | 折算基准金属 |
| `PriceFactor` | decimal(9,4) | 折算系数，例如 18K 对足金为 0.75 |
| `BuyPricePerGram` | decimal(18,4) | 回收/采购参考价/克 |
| `SellPricePerGram` | decimal(18,4) | 销售价/克 |
| `EffectiveFrom` | datetime | 生效开始 |
| `EffectiveTo` | datetime null | 生效结束，空表示长期 |
| `Status` | int | 0 启用，1 停用 |
| `Remark` | nvarchar(200) null | 备注 |
| 审计字段 |  | 创建人、创建时间等 |

索引建议：

- `TenantId + MetalItemId + EffectiveFrom`
- `TenantId + Status + EffectiveFrom`

价格取值规则：

```text
当前时间 >= EffectiveFrom
并且 EffectiveTo 为空或当前时间 < EffectiveTo
按 EffectiveFrom 倒序取第一条启用记录
```

价格记录不允许物理删除，只允许停用或补一条新价格，保证历史可追溯。

### 5.3 商品计价方式

新增独立字段 `PricingMode`：

- `1` 按件
- `2` 按克

`Unit` 继续表示条、颗、对、件、套，不参与计价方式判断。

建议同时增加 `LaborFee` 工费。工费按件收取，不随金价波动。

### 5.4 销售计算公式

按件商品：

```text
明细商品金额 = 成交单价 x 数量
```

按克商品：

```text
单件材料金额 = 单件重量 x 当前有效销售金价/银价
明细商品金额 = 单件材料金额 x 数量 + 工费 x 数量
```

如果业务希望工费也参与会员折扣，需要单独配置。默认建议工费不参与金价重算，但参与整单优惠。

订单金额计算顺序固定为：

```text
商品成交价合计
-> 明细会员折扣
-> 活动优惠
-> 手工调整
-> 抹零
-> 应收金额
-> 定金对冲
-> 本次实收
```

### 5.5 价格快照

`jy_sale_order_item` 新增以下快照字段：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `PricingMode` | int | 1 按件，2 按克 |
| `MetalPriceId` | bigint null | 使用的价格记录 |
| `MetalPricePerGram` | decimal(18,4) | 成交时单价/克 |
| `UnitWeight` | decimal(18,4) | 单件重量 |
| `TotalWeight` | decimal(18,4) | 总重量 |
| `LaborFee` | decimal(18,2) | 工费 |
| `LineAmount` | decimal(18,2) | 商品成交金额 |
| `DiscountRuleId` | bigint null | 命中的折扣规则 |
| `DiscountRate` | decimal(9,4) | 明细折扣率 |
| `DiscountAmount` | decimal(18,2) | 明细折扣金额 |
| `NetAmount` | decimal(18,2) | 明细折后金额 |
| `PriceSnapshotTime` | datetime null | 价格快照时间 |

草稿阶段可以按当前价预览。确认收款时服务端重新取价：

- 价格未变化：直接确认。
- 价格已变化：返回明确提示，要求用户确认按新价重算。
- 不允许静默改价。

销售退货必须使用原销售明细的快照价格，不按退货当天金价重算。

## 6. 会员等级折扣矩阵

### 6.1 不复用积分规则

`jy_point_rule` 负责积分和返现，不应混入商品折扣。否则后续调整积分规则会影响销售价格，职责不清。

### 6.2 新增 `jy_member_level_discount`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `Id` | bigint identity | 主键 |
| `TenantId` | nvarchar(64) | 租户 |
| `LevelId` | bigint | 会员等级 |
| `StyleItemId` | bigint null | 商品款式分类，空表示全部品类 |
| `PricingMode` | int | 0 全部，1 按件，2 按克 |
| `DiscountRate` | decimal(9,4) | 折扣率，0.85 表示八五折 |
| `Priority` | int | 优先级，数值越大越优先 |
| `Status` | int | 0 启用，1 停用 |
| `Remark` | nvarchar(200) null | 备注 |
| `DelFlag` | int | 逻辑删除 |
| 审计字段 |  | 创建人、创建时间等 |

索引建议：

- `TenantId + LevelId + Status`
- `TenantId + LevelId + StyleItemId + PricingMode`

### 6.3 折扣匹配优先级

对每一条销售明细：

1. 等级 + 具体品类 + 具体计价方式
2. 等级 + 具体品类 + 全部计价方式
3. 等级 + 全部品类 + 具体计价方式
4. 等级 + 全部品类 + 全部计价方式
5. 回退到 `jy_member_level.DiscountRate`

同一优先级存在多条时按 `Priority` 倒序，再按 `Id` 倒序，保证结果确定。

### 6.4 计算与保存

- 明细先计算商品金额，再应用命中折扣。
- 订单头 `DiscountAmount` 保存所有明细折扣和活动优惠的汇总。
- 建议新增 `MemberDiscountAmount`，单独保存会员折扣汇总。
- 明细保存 `DiscountRuleId`、`DiscountRate`、`DiscountAmount`、`NetAmount`。
- 现有 `ApplyMemberDiscount` 保留，收银员仍可取消本次会员折扣。

### 7.3 盘点流程

```text
创建盘点单
  -> 按门店/品类/供应商生成账面快照
  -> 扫码或手工录入实盘
  -> 系统计算差异
  -> 提交盘点结果
  -> 有权限人员确认
       -> 事务内调整货品或物料库存
       -> 写入库存流水
       -> 盘点单锁定为已确认
```

规则：

- 账面数量/重量必须在盘点开始时快照，后续库存变化不能影响已生成的盘点明细。
- 盘点确认时再次校验库存是否发生变化，变化超过允许范围时提示重新盘点。
- 正品盘点按件，物料盘点按克。
- 不允许盘点确认时直接改余额而不写流水。
- 盘亏不能把库存扣成负数。

### 7.4 综合盘点报表

- 盘点单号、类型、门店、盘点时间、盘点人、确认人
- 正品盘盈/盘亏数量和金额
- 物料盘盈/盘亏重量和金额
- 差异合计
- 按品类、供应商汇总
- 明细导出

## 8. 截料、旧料和料组合

### 8.1 设计原则

截料、旧料回收和料组合都属于库存形态转换，不应直接覆盖原商品或原材料。

必须回答三个问题：

1. 转换前是什么，属于谁。
2. 转换后生成了什么，剩余料去了哪里。
3. 成本如何分摊到新商品和剩余料。

### 8.4 转换流程

```text
选择来源货品/物料/客户旧料
  -> 录入输入重量和权属
  -> 录入输出新商品/新材料
  -> 录入损耗
  -> 分摊成本
  -> 确认转换
       -> 来源库存出库
       -> 新商品生成新的 GoodsNo/Barcode
       -> 剩余料进入物料库存
       -> 写入来源和去向流水
       -> 记录 SourceConversionId
```

客户旧料不能直接进入可销售库存。必须先区分：

- 客户寄料：库存可记，但权属不属于门店。
- 回收买断：完成结算后才转为自有库存。
- 换料：旧料入库和新料出库关联同一转换单。

### 8.5 成本分摊

默认按输出重量分摊：

```text
某输出项成本 = 输入总成本 x 该输出项重量 / 输出总重量
```

损耗成本可以：

- 计入新商品成本。
- 单独记为损耗。
- 按比例分摊到输出项。

建议默认计入新商品成本，同时保留损耗金额，便于毛利分析。

## 11. 数据迁移与兼容

### 11.1 新增字段默认值

- `PricingMode` 默认 1，保证历史商品继续按件。
- `InnerQty` 默认 1。
- `LaborFee` 默认 0。
- `DiscountRate` 默认 1。
- `PriceSnapshotTime` 允许为空，历史单据不回填虚假金价。

### 11.2 历史销售单

历史销售单没有金价快照，不能伪造。报表中按“历史按件单”处理，新单才使用完整快照。

### 11.3 历史库存

历史 `Qty` 迁移必须先做核对：

1. 导出货品、入库明细、销售明细。
2. 按 `GoodsNo` 对比 `Qty` 与入库明细的 `Qty`。
3. 确认哪些是单件唯一货品，哪些是内含数量。
4. 生成迁移清单，人工复核后再执行。

禁止直接批量执行 `UPDATE`。

## 12. 并发、事务与安全

### 12.1 物料库存

- 确认入库/出库时锁定物料行。
- 出库校验可用重量。
- 单据状态更新和库存更新在同一事务。
- 重复确认返回幂等结果，不重复写流水。

### 12.2 盘点

- 盘点开始保存账面快照。
- 确认时重新校验账面库存。
- 盘点调整和流水写入同一事务。
- 盘点单确认后不可直接修改明细。

### 12.3 销售

- 销售确认时重新校验商品状态和库存。
- 按克价格由服务端获取。
- 销售明细和库存扣减在同一事务。
- 退货不能超过可退数量和重量。

### 12.4 权限

- 物料成本、金价、折扣矩阵属于敏感数据，按权限控制查看和修改。
- 盘点确认、转换确认需要独立权限。
- 所有操作记录操作人、时间和业务单号。

## 13. 验收标准

### 13.1 物料

- 可新增两级物料分类。
- 可选择 `jy_supplier` 中的供应商。
- 入库后库存重量增加，流水记录正确。
- 出库后库存重量减少，不能出现负库存。
- 重复点击确认不会重复加减库存。
- 物料库存可按分类、供应商、关键字筛选。
- 物料流水可按物料和时间追溯。

### 13.2 贵金属计价

- 足金、18K、足银可分别维护价格。
- 价格有生效区间，销售取当前有效价。
- 按件商品按数量计价。
- 按克商品按重量和当前金价计算。
- 销售明细保存金价、重量、工费、折扣快照。
- 金价变化后历史单据金额不变。
- 退货使用原单价格快照。

### 13.3 会员折扣

- 不同等级可配置不同品类和计价方式折扣。
- 销售时自动匹配明细折扣。
- 精确规则优先于通用规则。
- 取消会员折扣后金额恢复。
- 订单头汇总金额与明细金额一致。

### 13.4 盘点

- 正品盘点和物料盘点可分别创建。
- 账面数量/重量在开始时快照。
- 实盘录入后自动计算差异。
- 确认后库存和流水同步变化。
- 综合报表能按正品、物料、品类、供应商汇总。

### 13.5 截料与旧料

- 转换单能记录输入、输出和损耗。
- 原商品/原材料出库有流水。
- 新商品生成新的条码和编码。
- 剩余料进入物料库存。
- 可追溯新商品来源于哪张转换单。
- 客户旧料权属和结算状态明确。

## 15. 待确认事项

以下问题会直接影响表结构和计算逻辑，实施前需要业务确认：

1. 按克销售时，工费是否参与会员折扣和活动优惠？
2. 金价变化后，草稿单是自动重算，还是必须人工确认？
3. 18K 是独立报价，还是按足金价格乘系数？
4. 物料分类是否只做两级，还是需要三级？
5. 物料出库是否需要审批，还是制单人可以直接确认？
6. 客户旧料是寄料、买断还是换料，三种是否都要支持？
7. 截料损耗成本计入新商品，还是单独记损耗？
8. 盘点差异是否需要财务复核后才能调整库存？
9. 正品盘点按“逐件是否存在”，还是按可售数量盘点？
10. 历史 `Qty` 数据由谁核对并确认迁移口径？

## 16. 结论

建议先实施第一期物料基础，同时完成 `Qty / InnerQty` 口径确认和历史数据核对。第二期再进入金价和按克销售，避免物料、货品、销售三条链路同时变更造成金额和库存不可追溯。

整体改造不建议一次性全部上线。按本文五期推进，可以在每一期交付后独立验收，降低对现有销售和库存业务的影响。
